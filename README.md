> [!NOTE]
> **Teads fork of [prebid/prebid-mobile-android](https://github.com/prebid/prebid-mobile-android).** Used for Teads tests and demo changes. Not a Teads SDK release.
>
> **Branches**
> - `master`: exact mirror of upstream `master`. Never commit or merge into it. It is synced with upstream from time to time, together with the release tags.
> - `main`: default branch. All Teads changes go here, through pull requests.
>
> **Updating from upstream**
> 1. Sync `master` (and tags) with upstream.
> 2. Open a PR that merges `master` into `main`. Merge, don't rebase: `main` is shared.
>
> **Keeping syncs easy**
> - Prefer new files in Teads folders (`teads` packages, `scripts/teads/`, `Examples/Teads/`) over edits to upstream files.
> - Keep unavoidable edits to upstream files small.
> - Send generic fixes upstream instead of carrying them here.
> - Don't commit internal hostnames, IPs or credentials. This repo is public.

# Prebid Mobile Android SDK

To work with Prebid Mobile, you will need access to a Prebid Server.
See [this page](https://docs.prebid.org/prebid-server/overview/prebid-server-overview.html) for options.

Visit the [Prebid documentation](https://docs.prebid.org/prebid-mobile/pbm-api/android/code-integration-android.html) to study the available integration approaches or autogenerated [API documentation](https://docs.prebid.org/prebid-mobile-android/index.html) for a description of available classes and methods.  

## Use Maven?

Easily include the Prebid Mobile SDK using Maven. Simply add this line to your gradle dependencies:

```
implementation 'org.prebid:prebid-mobile-sdk:3.4.1'
```

## Build from source

Build Prebid Mobile from source code. After cloning the repo, from the root directory run

```
scripts/buildPrebidMobile.sh
```

to output the final lib jar and package you a demo app.


## Test Prebid Mobile

Run the test script to run unit tests and integration tests.

```
scripts/testPrebidMobile.sh
```
